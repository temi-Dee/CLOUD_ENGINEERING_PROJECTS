Building My First AWS Cloud Engineering Project — Hosting a Personal Portfolio with S3, CloudFront, Route 53 & ACM

How I deployed a fully functional personal portfolio using core AWS services — and what I learned along the way.

Daniel Ayodele AWS Cloud Engineer & Cybersecurity Enthusiast
S3CloudFrontRoute 53ACMBeginner

As part of my AWS Cloud Engineering journey, I recently completed my first hands-on cloud project: deploying a fully functional personal portfolio and technical blog using core AWS services. This project was more than just hosting a website — it was an opportunity to understand how cloud infrastructure works behind the scenes.

Project Overview

The goal of this project was to build and deploy a personal portfolio and blog that showcases:

  • AWS cloud projects
  • Cybersecurity write-ups
  • Hands-on labs
  • Technical skills
  • Contact information

Instead of using traditional shared hosting platforms, I wanted to understand how professional cloud environments are structured using AWS services.

This project was built with HTML, CSS, and JavaScript, and deployed using:

Why I Chose AWS for This Project

AWS is one of the most widely used cloud platforms globally, and learning it practically is essential for cloud engineering and cybersecurity roles. This project introduced me to foundational concepts including object storage, CDN architecture, DNS routing, SSL/TLS encryption, bucket policies, and cloud-based website delivery.

Rather than learning these concepts theoretically, I implemented them directly in a real-world deployment.

Step 1 — Hosting the Website on Amazon S3

The first part of the project involved configuring an S3 bucket for static website hosting. This required:

  • Creating a globally unique bucket
  • Enabling static website hosting
  • Configuring index.html as the default root document
  • Writing bucket policies to allow public read access

One important lesson I learned was understanding the difference between the S3 REST endpoint and the S3 static website endpoint — a distinction that becomes critical when integrating CloudFront.

Key Insight: Always use the S3 website endpoint (not the bucket ARN) as the CloudFront origin. This ensures proper routing of requests to index.html.

Step 2 — Configuring HTTPS with ACM

To secure the website, I used AWS Certificate Manager (ACM) to request a free SSL/TLS certificate. One important detail I discovered is that CloudFront certificates must be created in the us-east-1 region, regardless of where the rest of the infrastructure is deployed.

The certificate was validated automatically using DNS verification through Route 53. This step helped me understand HTTPS encryption, certificate validation, and secure web communication.

Important: ACM certificates for CloudFront must always be requested in us-east-1 (N. Virginia) — even if your S3 bucket is in a different region.

Step 3 — Setting Up CloudFront CDN

After hosting the files in S3, I created a CloudFront distribution. CloudFront serves as a Content Delivery Network (CDN) that caches website files at AWS edge locations globally. Key configurations included:

  • Redirecting HTTP traffic to HTTPS
  • Adding custom domain names (CNAMEs)
  • Attaching the ACM certificate
  • Setting the S3 website endpoint as the origin

This significantly improves website performance and scalability for users across different geographic regions.

Step 4 — Connecting the Domain with Route 53

Next, I configured Route 53 to connect the custom domain to CloudFront. This involved creating A records and alias records, routing traffic directly to the CloudFront distribution. Once DNS propagation completed, the website became publicly accessible using HTTPS.

Challenges I Encountered

Like many cloud projects, this deployment came with a few troubleshooting moments. Some of the issues I encountered included:

  • Bucket permission errors when public access was blocked
  • Incorrect origin configuration (using bucket ARN instead of website endpoint)
  • SSL certificate delays during DNS validation
  • CloudFront cache propagation taking longer than expected

Working through these challenges helped me better understand how AWS services interact in real-world deployments.

Key Takeaways

One of the biggest lessons from this project is that cloud engineering is not only about writing code — it is also about understanding the infrastructure that powers applications. Even a simple static website involves networking, security, storage, DNS, caching, and deployment architecture.

Takeaway: This project gave me practical exposure to concepts commonly used in production cloud environments — and proved that hands-on learning is far more effective than theory alone.

Conclusion

Deploying my personal portfolio on AWS taught me that even beginner projects can provide deep insight into cloud architecture and infrastructure design. Every deployment challenge became a learning opportunity, and every AWS service introduced a new layer of understanding about how modern applications are delivered securely at scale.

This is only the beginning, and I'm excited to continue learning, building, and securing.
